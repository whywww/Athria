# Readiness 计算规则与科学依据

本文完整说明 Athria 当前的 Readiness 计算方法。规则以 [Rust 核心实现](../../crates/athria-core/src/readiness.rs)中的 `assess_readiness` 为准，持久化与重算由 [存储层](../../crates/athria-store/src/store.rs)负责。字段定义见[数据模型](data-model.md#wellness-fields)。

## 1. 评分目标与科学依据

Readiness 是结合身体恢复信号与近期训练历史形成的每日晨间估计，范围为 0–100。它不代表恢复百分比、医学诊断或伤病概率。

| 最终整数分 | 状态 | 含义 |
| --- | --- | --- |
| 70–100 | Ready | 按当前规则，训练准备度较好 |
| 45–69 | Caution | 按当前规则，宜谨慎安排训练 |
| 0–44 | Rest | 按当前规则，宜优先恢复 |
| 无法计算 | Insufficient data | 数据不足，不生成数值评分 |

基础分包含三个恢复维度：心脏恢复、睡眠、主观恢复。有效心脏维度可单独生成有限估计；没有心脏维度时，睡眠和主观恢复必须同时有效才评分。HRV 与心率是同一个维度；睡眠质量与时长也是同一个维度。训练历史不算独立恢复维度，不能仅凭训练少或没有记录就认定身体恢复良好。

科学依据与工程规则需要分别理解：

| 设计内容 | 研究支持的原则 | Athria 自定、仍需验证的规则 |
| --- | --- | --- |
| 心率与 HRV | 应结合个体变化、测量误差和训练背景解释，单个心率指标不能覆盖全部恢复状态 [[1]](#ref-1) | 28 天基线、7/14 日门槛、MAD 归一化、信号优先级、尺度下限与评分映射 |
| 主观疲劳 | 主观报告可提供客观指标之外的训练反应信息 [[2]](#ref-2) | `100 − subjectiveFatigue` 的分数映射及其权重 |
| 整次训练负荷 | session-RPE 方法使用整次训练感知强度与时长量化内部负荷 [[3]](#ref-3) | 总体/分组序列优先级、比较窗口、两天半衰期、历史分位数、证据权重及最多扣 15 分 |
| 睡眠 | 睡眠质量与时长值得监测，运动员的睡眠需求存在个体差异 [[4]](#ref-4) | 时长插值表、质量/时长组合权重及睡眠上限规则 |
| 负荷解释 | 训练负荷研究存在测量、时间窗口、缺失数据及外推等方法限制 [[5]](#ref-5) | 用异常程度修正准备度，不使用固定 ACWR 安全区间或换算伤病概率 |

**这些研究支持指标选择与监测思路，不直接验证本文的综合公式。** 40%/35%/25% 权重、状态分界、基线门槛、扣分映射、严重信号上限等都是产品规则；不能将这些具体数字表述为论文给出的生理阈值。

## 2. 评估日期、输入与有效值

### 2.1 晨间评估日期

定义 `D` 为评估日，`E = D−1` 为前一日，日期均按日历日理解。

| 输入 | 使用日期 | 说明 |
| --- | --- | --- |
| HRV、静息心率、主观疲劳 | E | 昨日的日级身体状态 |
| 睡眠评分、睡眠时长、睡眠平均心率 | E | 睡眠存于入睡当晚，表示 E 晚至 D 日的睡眠 |
| 当前训练压力 | D−7 至 D−1，含两端 | 只使用已完成的实际训练 |
| 心脏恢复基线 | E−28 至 E−1，含两端 | 排除目标日 E |
| 历史训练压力 | D−28 至 D−1 的各个晨间 | 每个历史晨间使用其之前 7 天训练 |

例如，10 月 16 日晨间估计使用 10 月 15 日的心脏指标与主观疲劳、10 月 15 日晚至 16 日的睡眠，以及 10 月 9–15 日的训练。10 月 16 日完成的训练影响次日估计。

该分数用 E 日的 wellness 记录计算并保存在 E 日；App 在 D=E+1 展示它。因此今天在 App 看到的 readiness 表示截至前一日的健康状态，记录顶层的 `assessmentDay` 是展示日 D。

现有身体指标没有可靠的测量时刻，不能将日级记录宣称为晨间测量，也不能把 `updatedAt` 当作测量时间。此评分表示“依据昨日日间状态与昨夜睡眠形成的晨间估计”，不是当天训练后的动态状态。

### 2.2 训练日期与去重

- 仅取相同用户、`status = completed` 的规范化训练历史，排除计划训练及未来日期。
- `timePrecision = exact`：将 `startAt` 转换到用户时区后取得日期。
- `timePrecision = date_only`：优先使用记录自身时区，缺失时回退用户时区，以保留来源日历日期；不推算小时级恢复间隔。
- 使用已完成规范化去重的训练；核心也忽略重复出现的相同训练 ID。
- 为覆盖历史压力窗口，最多读取 D−35 至 D−1 的训练。

### 2.3 有效值

| 字段 | 参与计算的有效值 | 零值含义 |
| --- | --- | --- |
| HRV、静息心率、睡眠平均心率 | 有限数，且大于 0 | 不可用 |
| `sleepScore`、`subjectiveFatigue` | 有限数，0–100 | 有效评分，不是缺失 |
| `sleepSeconds` | 0–86,400 的整数秒 | 明确记录零睡眠 |
| 整次训练 `rpe` | 1–10 的整数 | 不在有效范围内 |
| `durationMinutes` | 非负整数 | 明确记录零时长，可形成零负荷 |
| API 负荷、`atl`、`ctl` | 非负有限数 | 有效零负荷 |

缺字段、`null`、非有限数或越界值视为缺失，不转换为零。**无训练记录的日期默认无训练，负荷为零**；这与“已经记录训练，但某个字段缺失”不同。本算法以已有记录为准，不读取或扩展同步覆盖信息。只读取当前统一字段，不在评分器内处理已退休字段。

## 3. 心脏恢复分 C

### 3.1 信号优先级与个人基线

心脏恢复分包含 HRV 信号和心率信号：

| 信号 | 首选字段 | 回退字段 |
| --- | --- | --- |
| HRV | `hrvRmssdMs` | `hrvSdnnMs` |
| 心率 | `restingHeartRateBpm` | `avgSleepingHeartRateBpm` |

只有首选字段当前值与基线都可用时才使用它；否则尝试回退字段。不同字段分别建立基线，不将 RMSSD 与 SDNN、静息与睡眠心率混合比较。

每个字段的基线要求：

1. 与目标记录相同用户、相同字段、相同 `source`。
2. 日期位于 E−28 至 E−1，排除 E 及之后的记录。
3. 当前值和历史值均为正有限数。
4. 至少 7 个不同有效日；同一天不重复增加样本数。

7–13 个有效日属于初步基线，14 日以上属于较充分基线。基线不足时不使用人群平均值代替。

研究支持重视个体变化、测量条件及训练背景，但不直接给出这里的基线天数或回退优先级。相同来源也不能保证设备、测量姿势与时长始终一致，这仍是输入数据的限制。[[1]](#ref-1)

### 3.2 中位数、MAD 与标准化

对选定历史数列 `x`：

```text
m = median(x)
MAD = median(|x − m|)
clamp(x, a, b) = min(max(x, a), b)
```

中位数与 MAD 用于减少异常值对基线的影响。`1.4826 × MAD` 是一种常见的正态一致性尺度换算；使用该系数不表示生理数据已被证明服从正态分布。尺度下限防止历史读数几乎不变时，微小变化被过度放大。

HRV 对当前值和每个历史值先取自然对数：

```text
x = ln(历史 HRV)
c = ln(当前 HRV)
zHRV = (median(x) − c) / max(1.4826 × MAD(x), 0.05)
```

心率直接使用 bpm：

```text
zHR = (当前心率 − median(历史心率))
      / max(1.4826 × MAD(历史心率), 3 bpm)
```

`zHRV` 在 HRV 低于常态时为正；`zHR` 在心率高于常态时为正。它们是本算法的异常程度指标，不是医学检验的诊断值。

### 3.3 信号映射与组合

```text
信号分 = 85 − 20 × clamp(z, 0, 3)
```

| z | 信号分 |
| --- | ---: |
| 不大于 0 | 85 |
| 1 | 65 |
| 2 | 45 |
| 不小于 3 | 25 |

有利方向的读数最多得到 85 分；HRV 异常升高不会无限加分，也不等于已证明恢复充分。

- 两个信号都有效：`C = 0.60 × HRV分 + 0.40 × 心率分`。
- 只有一个有效：`C = 该信号分`，并记录部分心脏信号缺失。
- 两个都不可用：心脏恢复维度缺失。

信号映射及组合权重为 Athria 自定参数，不由文献中的具体实验结果直接换算而来。

## 4. 睡眠分 S 与主观恢复分 F

### 4.1 睡眠时长分

将有效 `sleepSeconds` 除以 3,600 得到小时数 `h`，按以下节点线性插值：

| 睡眠小时数 | 0 | 4 | 6 | 7 | 8 及以上 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 时长分 | 0 | 25 | 60 | 80 | 90 |

若 `h` 位于相邻节点 `(h0, s0)` 与 `(h1, s1)` 之间：

```text
时长分 = s0 + (h − h0) / (h1 − h0) × (s1 − s0)
```

例如 5 小时为 42.5 分，7.5 小时为 85 分。8 小时以上保持 90 分，不继续奖励长睡眠，也不仅凭睡眠较长就作负面判断。

这是成人场景的产品默认映射，不代表每个人都需要相同睡眠时长。运动员睡眠共识建议结合个人睡眠需求；该文献并未验证本表的具体分数。[[4]](#ref-4)

### 4.2 睡眠组合

有效 `sleepScore` 直接使用其 0–100 值，不再分档。

| 数据情况 | 睡眠分 S |
| --- | --- |
| 质量与时长均有效 | `0.60 × sleepScore + 0.40 × 时长分` |
| 仅质量有效 | `sleepScore` |
| 仅时长有效 | `时长分` |
| 都缺失 | 睡眠维度缺失 |

例如，质量评分 90、时长 7 小时，则 `S = 0.6 × 90 + 0.4 × 80 = 86`。两项始终只构成一个恢复维度。

### 4.3 主观恢复

```text
F = 100 − subjectiveFatigue
```

疲劳为 0 时，F 为 100；疲劳为 100 时，F 为 0。缺失时不从设备推测，也不沿用更早一天的报告。

主观指标可提供训练反应信息，但研究中问卷与评分尺度存在差异；不能据此宣称此单项字段、线性映射或 25% 权重已经过验证。[[2]](#ref-2)

## 5. 基础分 B 与最低评分条件

| 恢复维度 | 记号 | 默认权重 |
| --- | --- | ---: |
| 心脏恢复 | C | 0.40 |
| 睡眠 | S | 0.35 |
| 主观恢复 | F | 0.25 |

满足评分条件时，对可用维度的权重重新归一化：

```text
B = Σ(有效维度分 × 默认权重) / Σ(有效维度的默认权重)
```

三项齐全时：

```text
B = 0.40C + 0.35S + 0.25F
```

例如，主观疲劳缺失时：

```text
B = (0.40C + 0.35S) / 0.75
```

有效心脏维度可独立评分，此时 `B = C`。HRV 或心率只有一项有效，只要该信号当前值与同源个人基线均有效，也可形成心脏维度；结果标为数据有限。没有心脏维度时，睡眠与主观恢复必须同时有效；仅睡眠、仅主观恢复或没有恢复维度时不生成分数。

睡眠和主观疲劳是可选补充，不补零、不因缺失额外扣分。训练负荷仍可修正心脏单维度估计，但不会替代缺失的身体恢复信号。上述权重和评分门槛均为工程规则，研究不直接验证单维度综合估计的有效性。心脏指标正常不能证明睡眠充足、肌肉恢复或主观状态良好。[[1]](#ref-1) [[2]](#ref-2)

例如 C=85，睡眠和主观疲劳缺失，已有训练负荷修正为4且g=1，则B=85，最终81分、Ready、数据有限。卡片显示“仅基于心脏指标”；仅HRV或心率时进一步注明具体信号。步数暂作活动背景，SpO₂暂作独立提示，不映射为恢复分；ATL/CTL仅用于已有负荷回退。

## 6. 近期负荷统计与个人常态修正

近期训练统计不再要求足够长的个人历史。即使暂不能参与评分，也返回最近七天训练次数、总时长、已填写RPE次数、已知Session-RPE总负荷及压力。缺少字段时保留已知部分，不能把它称为完整总负荷。

### 6.1 负荷选择与分组

每个候选序列按以下优先级尝试：

| 优先级 | 字段或计算值 | 约束 |
| --- | --- | --- |
| 1 | `rpe × durationMinutes`，对应 `sessionRpe` | 重新计算；整次训练RPE为1–10整数，时长为非负整数分钟；不使用力量组RPE |
| 2 | `trainingLoad` | 使用来源保留的非负有限值 |
| 3 | `powerLoad` | 同上 |
| 4 | `hrLoad` | 同上 |
| 5 | `paceLoad` | 同上 |

选择顺序如下：

1. 最近七天全部训练都有有效RPE，且总体RPE序列符合评分门槛时，使用全部项目合并的RPE序列。
2. 否则按近期训练的`type`分组。各组历史也仅取相同`type`，按表中顺序选择第一个可评分候选。
3. 某组所有候选都不可评分时，保留优先候选的已知统计与原因；优先展示有有效近期值的候选，全部无值时保留RPE候选。
4. 未知训练项目可以参与RPE统计，但不尝试API字段的项目比较。

API不再要求整个窗口只有一种训练项目。游泳与步行可以各自比较；不同项目或字段的原始负荷不会直接相加。只有归一化后的修正分才能合并。

session-RPE研究支持用整次训练感知强度与时长量化内部负荷，但不验证本文的跨来源优先级、分组或评分映射。[[3]](#ref-3)

### 6.2 近期压力与历史窗口

对任一晨间T：

```text
P(T) = Σ[Lᵢ × 2^(−aᵢ/2)]
训练日期 ∈ [T−7, T−1]
aᵢ = (T−1) − 训练日期，单位为日历天
```

昨天的权重为1，前天约0.707，三天前为0.5。同日多次训练分别累计，按项目比较时仅包含该项目。

对D−28至D−1的28个历史晨间分别计算压力。无训练记录的窗口是有效零压力窗口；如果窗口中已记录训练缺少候选负荷，整个窗口不参与该候选的比较。近期缺失时仍展示已知负荷，但该候选不能参与评分。

候选能够评分需要同时满足：

- 当前七天所有已记录训练均有候选字段，且累计结果有限。
- 至少7个有效历史压力窗口。
- D−35至D−2内至少3个不同有效参考训练日；D−1不进入参考训练日统计。

不再要求至少21天跨度，也不要求历史压力中位数大于零。参考训练按日期去重，因此同日拆分不会提高历史支持权重。历史压力窗口可能重叠，不能当作独立统计样本。

两天半衰期仍为工程默认值，不代表所有人或训练项目的真实恢复速度。次数、时长和强度不再另外重复扣分。

### 6.3 历史分位数与原始修正

设H为候选的有效历史压力数列：

```text
p = (H中小于当前压力的数量 + 0.5 × H中等于当前压力的数量) / |H|
原始修正 = 15 × clamp((p − 0.75) / 0.25, 0, 1)
```

| 历史分位数p | 原始修正 |
| --- | ---: |
| 不高于75% | 0 |
| 80% | 3 |
| 90% | 9 |
| 100% | 15 |

两值相差不超过`1e−9 × max(1, |当前值|, |历史值|)`时判为相同，降低浮点误差对排名的影响。

大量零压力不会再造成MAD分母为零。例如当前与历史全为零时，分位数为50%、原始修正为0；如果历史已有至少3个有效零负荷训练日，该序列也能满足样本门槛。完全没有参考训练时，则只统计零负荷，不伪造个人基线。

分位数只描述当前压力在已有记录中的相对位置，不表示疲劳概率、伤病风险或恢复百分比。75%阈值和线性映射是待验证的工程规则。[[5]](#ref-5)

### 6.4 历史支持权重与分组汇总

```text
跨度 = 最晚参考训练日 − 最早参考训练日 + 1
q = min(有效历史窗口数 / 28, 1)
    × min(不同参考训练日数 / 7, 1)
    × min(跨度 / 28, 1)
组修正 = 原始修正 × q
```

不符合最低门槛时q为0；符合门槛后，短历史可以小幅参与，随历史增加逐渐提高影响。q是工程上的证据权重，不是统计置信概率。

使用总体RPE序列时，时长占比为1；采用项目分组时：

```text
组时长占比 = 该组最近七天时长 / 全部近期训练时长
合并后训练修正 = Σ(可评分组修正 × 组时长占比)
```

不可评分组贡献零，但不把其份额重新分配给其他组。全部近期训练时长为零时，训练序列修正为零。原始负荷和压力仅按各自量纲展示，界面不提供混合量纲的原始总和。

### 6.5 ATL/CTL互斥回退

只有没有任何训练组可评分时，才尝试E日的ATL/CTL：

- 当前两项必须为非负有限数且来源相同。
- E−28至E−1内至少7个不同有效配对日，历史两项都与当前来源一致、用户一致。
- 对每个有效日计算`Q = atl − ctl`，以当前Q和历史Q计算相同的经验分位数。
- 当前`Q ≤ 0`时原始修正为0；否则使用相同的分位数映射。

```text
qATL = min(有效配对日数 / 28, 1)
       × min(配对日期含首尾跨度 / 28, 1)
ATL/CTL修正 = 原始修正 × qATL
```

ATL/CTL使用时不再叠加训练组修正，已知训练统计仍保留。配对不足7日时，仅展示当前差值与基线进度。

`form`不额外参与，孤立的form不能替代配对值；`intensity`可能超过100，不作通用百分制疲劳值。没有可评分训练组或ATL/CTL时，修正为0，并区分字段不完整、基线建立中与无训练记录。

不使用固定ACWR安全区间，也不将CTL直接解释为恢复能力或伤病概率。[[5]](#ref-5)

## 7. 最终分数、回退与数据质量

### 7.1 上限与舍入顺序

先确定下表中的最低严重信号上限，再对训练负荷的影响作保守限制。恢复状态已经不利时，不再机械地追加全部负荷修正：

```text
W = min(B, 严重信号上限；无上限时使用100)
g = clamp((W − 45) / 25, 0, 1)
A = 合并后训练修正 × g
R未舍入 = clamp(B − A, 0, 100)
```

W达到70时g为1；W在45至70之间时线性减弱；W不高于45时g为0。恢复维度不足、没有B时，g为0，仅返回训练统计，不生成Readiness。

这是避免过度叠加负面信息的工程政策，不代表已证明训练负荷与wellness的统计独立性，也不保证完全消除同一疲劳反应的重复计量。

再按有效的当日输入设置上限：

| 条件 | 分数上限 |
| --- | ---: |
| `subjectiveFatigue ≥ 75` | 44 |
| `50 ≤ subjectiveFatigue < 75` | 69 |
| 明确记录 `sleepSeconds = 0` | 44 |
| 有效 `sleepSeconds < 14,400`，或有效 `sleepScore ≤ 25` | 69 |

```text
R受限 = min(R未舍入, 所有适用上限)
最终分数 = round(R受限)
```

多个上限取最低值；没有上限时保持原分数。所有中间分数保留精度，只在最后舍入。最终分数为非负数，Rust 的 `round` 在恰好半分时向上舍入。状态只根据最终整数分确定，不再额外按单项字段修改状态。

这些上限用于防止严重单项信号被其他高分抵消，属于保守产品规则，不是论文给出的临床或运动禁忌阈值。

### 7.2 计算示例

| 场景 | 计算 | 结果 |
| --- | --- | --- |
| 三维度与负荷齐全 | C=85；质量90、睡眠7小时使S=86；疲劳20使F=80；B=84.1。若压力分位数90%、q=1，则合并修正9、g=1、A=9 | 75分，Ready |
| 睡眠缺失 | C=85、疲劳50使F=50；B=(0.40×85+0.25×50)/0.65≈71.54；负荷未纳入，A=0；疲劳上限69 | 69分，Caution |
| 明显主观疲劳 | C=85、S=90、疲劳75使F=25；B=71.75；A=0；适用上限44 | 44分，Rest |
| 只有心脏维度 | HRV或心率至少一项有有效个人基线；C=85，A=0 | 85分，Ready，数据有限 |

### 7.3 字段缺失回退表

| 场景 | 行为 |
| --- | --- |
| RMSSD 当前值或基线不可用 | 尝试具有独立基线的 SDNN |
| 静息心率当前值或基线不可用 | 尝试具有独立基线的睡眠平均心率 |
| 心脏信号只剩一项 | 保留心脏恢复维度，记录部分信号缺失 |
| 心脏信号均不可用 | 移除心脏恢复维度 |
| 睡眠质量与时长只剩一项 | 使用有效的一项，仍只算一个维度 |
| 主观疲劳缺失 | 移除主观恢复维度，不猜测、不沿用 |
| 一个恢复维度缺失，另两个有效 | 对有效维度重新归一化 |
| 只有心脏维度 | B=C，允许有限估计；保留负荷修正 |
| 无心脏维度且睡眠或主观恢复缺失 | 不生成分数，即使存在训练或 ATL/CTL |
| 总体RPE序列不可用 | 按项目选择可比较的候选；所有组都不可评分时再尝试ATL/CTL |
| 所有负荷路径均不可评分 | A=0，保留已知统计并说明字段缺失或基线进度 |
| 无训练记录日期 | 默认无训练、负荷为零；不要求同步覆盖证明 |
| E 日数据不足 | 不拿更早的整份 Readiness 替代 D 日估计 |

体重、体脂、VO₂max、步数、SpO₂ 和呼吸频率不直接进入本公式；可以用于独立趋势解释。已有 `readiness` 是计算输出，不作为输入递归计算。

### 7.4 数据质量

| 数据质量 | 返回值 | 条件 |
| --- | --- | --- |
| 不足 | `insufficient` | 无法生成分数 |
| 较充分 | `sufficient` | 三个恢复维度均有效；HRV与心率两个信号各至少14个基线日；心率采用静息心率而非睡眠代理；选用路径字段完整、各相关训练组q达到1且时长份额完整覆盖，或合格ATL/CTL回退的q达到1 |
| 有限 | `limited` | 能生成分数，但未满足上述全部充分条件 |

仅心脏维度的估计始终标为有限；缺失不会额外压低分数，也不会将状态强制改为Caution。卡片保留一行信息范围提示，帮助详情说明未纳入睡眠和主观疲劳，避免将正常心脏指标解释为完整恢复。

这些标签描述现有记录支持程度，不是概率或准确率。按照产品约定，无记录日期计为无训练，不再用同步覆盖信息改变这一默认值。

`missingReasons`记录恢复维度缺失、部分心脏信号、初步心脏基线、训练负荷字段不完整和训练基线建立中等原因。训练明细另外区分无训练、字段不完整、基线建立中、已纳入但未达到阈值、已修正、恢复信号已不利而未追加扣分及有效恢复维度不足。

## 8. 接口、持久化与验证范围

### 8.1 核心输出与缓存

Rust 核心统一返回 `ReadinessAssessment`；其他调用方不应维护另一套评分公式。

| 输出字段 | 含义 |
| --- | --- |
| `assessmentDay` | 对应晨间日期 D |
| `score`、`status` | 最终分数与状态；无法评分时score为null |
| `cardiacScore`、`sleepScore`、`subjectiveScore` | 三个恢复维度的分数或null |
| `baseScore` | 重归一化后的基础分或null |
| `loadAdjustment`、`loadMethod` | 实际进入公式的A与选用路径；多个组使用mixed标识 |
| `trainingLoad` | 近期统计、总体或项目分组、历史样本与跨度、分位数、证据权重、合并修正和wellness影响系数 |
| `scoreCap` | 最低适用上限或null |
| `dataQuality`、`missingReasons` | 数据质量与缺失说明 |
| `hrvField`、`heartRateField` | 实际使用的心脏字段 |
| `hrvBaselineDays`、`heartRateBaselineDays` | 实际基线有效日数量 |
| `algorithmVersion` | 内部计算规则标识，用于识别派生结果 |

- 数值评分继续存于 E 日的 `wellness.fields.readiness`，来源为 `athria`，含义是 D 日晨间估计。
- 记录顶层的 `readinessAssessment` 保留分项、缺口及对应晨间日期。即使无法评分，也可保存说明；数值字段本身移除，不存伪零分。
- 原始 wellness 解析不信任外部提交的派生明细；写入流程由核心重新生成。
- wellness、训练RPE、时长、导入负荷、删除、去重及用户时区变化后，事务内重新计算该用户的历史缓存；当前实现遍历该用户已有wellness记录，不只更新当天。
- 可写打开数据库时回填当前计算规则的结果；结果未变化时不更新其时间戳。只读检查不写入、不回填。
- Overview读取E日的持久化分数，并将明细说明为D日晨间估计。历史补录可以修订结果，因此当前缓存不是不可变的原始预测日志。
